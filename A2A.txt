一、角色定义（固定，精简版）
==================================================

[PM-AGENT]
- 角色：项目经理 / 指挥者（唯一管理者）
- 职责：
  1. 分解任务、分配优先级和里程碑。
  2. 审核交付质量并做 Go/No-Go 决策。
  3. 管理风险与阻塞升级。
  4. 维护 `A2A.txt` 规则和节奏。

[DEV-FULLSTACK]
- 角色：全栈开发（前后端统一一个 Agent）
- 职责：
  1. 实现 Go 后端统一接口与 Adapter Registry。
  2. 落地 Codex Adapter（会话发现/详情/事件/continue）。
  3. 实现前端设置页与连接测试能力。
  4. 维护 API 契约一致性（实现与文档同步）。

[QA-AGENT]
- 角色：测试与验收
- 职责：
  1. 按 `docs/test-plan-mvp.md` 执行核心用例。
  2. 按 `docs/adapter-conformance-test.md` 验证适配器一致性。

三、协作规则（固定）
==================================================

1. 状态流转：
   - `TODO -> IN_PROGRESS -> REVIEW -> DONE`
   - 阻塞：`IN_PROGRESS -> BLOCKED -> IN_PROGRESS`

2. 文档一致性：
   - API 行为变更必须同步更新 `docs/api.md` 与 `docs/api-contract-v1.md`。

3. 质量门禁：
   - 关键用例未通过，不得标记 `DONE`。
   - 存在 `S0/S1` 缺陷，不得进入发布结论。

4. 决策记录：
   - 关键决策由 PM 以 `DECISION` 形式写入对话区。
